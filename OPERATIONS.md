# OPERATIONS.md

All commands run from the repository root.

## 1. Prerequisites

- **uv** — Python toolchain (`curl -LsSf https://astral.sh/uv/install.sh | sh`).
  Needed because this machine lacks `python3.12-venv` (D-005).
- **Node.js 20+** and npm (present: Node 24.16.0).
- **PostgreSQL 16** running locally (present).
- `make`, `git`.

## 2. First-time installation

```bash
cp .env.example .env       # then set DATABASE_URL / passwords
make setup                 # venv + editable backend install + npm install
make migrate               # apply Alembic migrations to DATABASE_URL
make check                 # lint + tests must be green
```

### Database installation (this machine, already done — reference)

System installs need root; `sudo` here requires an interactive password, so
they were performed with a graphical prompt:

```bash
pkexec /usr/bin/env DEBIAN_FRONTEND=noninteractive /usr/bin/apt-get install -y postgresql
```

Role/database provisioning (idempotent; run as the `postgres` OS user):

```sql
CREATE ROLE retire_app LOGIN PASSWORD '<generate a strong password>';
ALTER ROLE retire_app CREATEDB;          -- dev only; see SECURITY.md
CREATE DATABASE retirement OWNER retire_app;
```

The live credentials live **only** in `.env` (mode 600, gitignored).

## 3. Daily startup / shutdown

```bash
make backend     # API  → http://127.0.0.1:8010/api/health
make frontend    # UI   → http://127.0.0.1:5173  (proxies /api to the API)
```

Stop with Ctrl-C in each terminal. Data persists in PostgreSQL; nothing
in-flight is lost. Confirm clean shutdown with `ss -ltn | grep -E '8010|5173'`
(should show nothing).

Port note: `.env` sets `APP_PORT=8010` because 8000 is permanently taken on
this machine (KI-001, D-006). The Vite proxy reads the same `.env` value.

## 4. Migrations

```bash
make migrate                              # upgrade to head
make migrate-revision MSG="add accounts"  # autogenerate a new revision
cd backend && ../.venv/bin/alembic history # review chain
cd backend && ../.venv/bin/alembic current
```

Always review autogenerated migrations before committing, and run
`make test` afterwards (tests replay migrations from scratch).

## 5. Backup and restore (procedure — restoration not yet exercised: KI-004)

```bash
TS=$(date +%Y%m%d-%H%M%S)
mkdir -p backups
pg_dump -h 127.0.0.1 -U retire_app -d retirement -Fc -f "backups/retirement-$TS.dump"
```

Restore into a clean database (this REPLACES data — confirm first):

```bash
dropdb  -h 127.0.0.1 -U retire_app retirement
createdb -h 127.0.0.1 -U retire_app -O retire_app retirement
pg_restore -h 127.0.0.1 -U retire_app -d retirement "backups/retirement-$TS.dump"
```

- `backups/` is gitignored and should live **outside** the repo when it
  matters. Unencrypted dumps contain sensitive financial data — store
  accordingly (SECURITY.md).
- Before major upgrades, take a user-triggered backup first.

## 6. Production deployment (docker-compose) — **NOT YET VERIFIED (INFRA-004)**

```bash
# on the server, after copying the repository:
$EDITOR .env            # change POSTGRES_PASSWORD and DATABASE_URL!
docker compose up -d --build
# web UI:    http://<server>:8080
# API only:  127.0.0.1:8010 inside the server (never published publicly)
```

What the stack does: `db` (Postgres 16, volume, **port not published**),
`api` (runs `alembic upgrade head` then uvicorn, host-published only on
loopback), `web` (nginx serving the built SPA + proxying `/api`, CSP header
enabled). Missing pieces before real exposure: HTTPS termination and
AUTH-001 (SECURITY.md). Do not expose the database port.

## 7. Upgrades

```bash
git pull
make setup && make lock   # refresh deps if requirements changed
make migrate              # apply schema changes
make check
```

Take a backup first (section 5).

## 8. Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| `address already in use` on startup | Port conflict (8000 is taken here). Check `.env` `APP_PORT`; `ss -ltnp \| grep :<port>` |
| Tests fail with "PostgreSQL is not reachable" | Server not running: `service postgresql status` / start it; check `.env` DATABASE_URL |
| `permission denied for database` | Role/password mismatch — verify `.env` against `psql -h 127.0.0.1 -U retire_app -d retirement` |
| `pg_isready` fails | `sudo service postgresql start` (or pkexec per section 2) |
| `uv: command not found` | Reinstall uv; ensure `~/.local/bin` is on PATH |
| Vite shows "API unreachable" | Backend not running, or `APP_PORT` changed in `.env` without restarting Vite |
| Migration applied to wrong DB | `alembic current` shows the DB it touched; DATABASE_URL env var wins over `.env` |
| `make` recipe errors | Ensure GNU make and that `make setup` was run once |

## 9. Health checks
