  partial unique index (per-household), allocation uniqueness, date-order

## Features partially implemented (spec gaps inside DATA-001's area)

- **Financial goals / planning preferences** — not modeled yet; deferred
  to DATA-012 (DECISIONS D-012).
- **Employment periods** (multi-segment career history) — only a single
  `retirement_date` per person exists; with DATA-012.
- **Structured survivor/beneficiary assumptions** — income streams have
  survivor rules; plan-level beneficiary modeling waits for the estate/calc
  phase (fields available via `plan.notes` meanwhile).
- **Per-account withdrawal rules / contribution rules** — balances,
  returns, fees, and annual contributions exist; withdrawal ordering and
  penalty rules are semantics of the CALC phase (spec §11).
- **Spending adjustment steps** — currently **one** age/percent adjustment
  per expense row; workarounds: split the expense into two rows with
  different dates until multi-step support lands.
- **Filing status over time** — one value per household; changes over time
  are expressed by scenario plans until a dated-rule model is needed.
- **API/UI layer for the model** — none yet (DATA-002/UI-002).
